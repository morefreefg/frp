## 本轮真实运行

在 Mac arm64 及 Linux amd64 各运行一套本次构建的程序。均使用临时随机密钥、
独立的两端配置和仅监听 loopback 的测试端口，完成：

1. 从通过 stdin 创建的加密 YAML 启动 frps / frpc。
2. TCP 代理真实访问本地 HTTP 服务并核对响应。
3. 验证内嵌 Dashboard 可访问，未认证的配置读取返回 401。
4. 服务端保存配置后仍为密文；旧版本保存返回 409。
5. 客户端保存并 reload，配置仍为密文，原 TCP 转发继续工作。
6. 通过现有 Store 管理 API 新增代理，独立 Store 文件为密文，新代理可转发。
7. 重启 frpc，确认可从加密 Store 恢复新增规则并继续转发。
8. 删除进程密钥环境变量后的配置校验失败，不回退为明文。

Mac 上另外通过 Ego Lite 实际打开两端配置页，修改并点击保存。
服务端显示重启生效提示，客户端完成原有确认弹窗并显示保存/重载成功。
保存后检查服务端主文件、客户端主文件与 Store 的密文头、文件权限和明文缺失。
